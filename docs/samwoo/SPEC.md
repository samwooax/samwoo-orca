## 1. 제품 정의와 지원 범위

SAMWOO-ORCA는 upstream Orca 데스크톱 앱을 기반으로 다음을 결합한 사내 협업 도구다.

- Nextcloud 기반 팀 워크스페이스와 파일 동기화
- Hermes·Claude·GPT 계열 모델을 사용하는 프로필별 AI 팀 채팅
- 프로필별 팀·워크스페이스 메신저와 알림
- 회사 메일 IMAP/SMTP 연동 및 메일 첨부파일의 워크스페이스 직행 저장
- upstream Orca의 에이전트, Git worktree, 터미널, 편집기, 브라우저, SSH·WSL 실행 기능
- Windows 사내 설치·자동 업데이트 경로

주 사용자는 비개발 직원을 포함한 사내 사용자이며 목표 동시 접속 규모는 약 100명이다. 중앙 API와 공유 데이터는 프로필 단위로 격리한다. 확장 트리거는 동시 사용자 300명 이상 또는 SQLite 단일 VPS의 실측 병목이며, 그 전에는 Redis·Kafka·클러스터를 도입하지 않는다.

SAMWOO 회사 배포의 기준 플랫폼은 Windows다. upstream 코드의 macOS·Linux·Windows, WSL, SSH 호환성은 유지하며 SAMWOO 전용 코드는 특정 로컬 OS나 경로 구분자를 가정하지 않는다.

## 3. 전체 구조와 네트워크 현황

```text
[사용자 Windows 노트북 / SAMWOO-ORCA]
  ├─ Tailscale HTTP ──> [인증·협업 VPS :8823]
  │                      ├─ 인증/세션
  │                      ├─ 워크스페이스·댓글 API
  │                      ├─ 프로필 메신저 API
  │                      ├─ 메일 IMAP/SMTP 중계
  │                      └─ SQLite + Nextcloud WebDAV
  ├─ Tailscale SSH ───> [Hermes 호스트]
  │                      └─ 프로필별 Hermes 컨테이너/ACP 또는 Claude CLI
  └─ HTTPS ───────────> [GitHub Public Release]
                         └─ 업데이트 확인·설치 파일/블록맵 다운로드
```

| 대상 | 주소·프로토콜 | 용도 | 2026-08-08 상태 |
|---|---|---|---|
| 인증·협업 VPS | `http://100.116.18.119:8823` / Tailscale HTTP | 로그인, 세션, 워크스페이스, 메신저, 메일 | 로그인 검증 응답 확인. 연속 API 점검 중 일부 타임아웃 관측 |
| SSE 예정 경로 | 위 서버의 `GET /events` | 메신저 실시간 이벤트·프레즌스 | **404 확인 — 운영 미배포** |
| Hermes 호스트 | `hermes@100.68.242.83` / Tailscale SSH | 팀봇 ACP·Claude 실행 | SSH 연결 확인 |
| Hermes 대시보드 | 원격 `4862` 포트 | 대시보드 터널 | 코드에 구성, 이번 감사에서 UI 미확인 |
| 회사 메일 | `play.samwooeleco.com:993` IMAPS, `:587` SMTP STARTTLS | 받은메일·본문·발송·첨부 처리 | 코드 기본값. 실계정 송수신은 미실행 |
| Nextcloud | VPS의 WebDAV 설정 | 공유 워크스페이스 파일 저장 | 코드 경로 확인, 관리 화면 미확인 |
| 업데이트 피드 | `github.com/samwooax/samwoo-orca/releases` / HTTPS | 공개 릴리스 업데이트 | `v1.4.182` 공개 확인 |

Tailscale MagicDNS는 관리 Windows PC에서 해석 실패한 이력이 있어 현재는 IP를 직접 쓴다. 엔드포인트는 `src/shared/samwoo-service-endpoints.ts`에서 중앙 관리한다. 클라이언트 노트북에 외부에서 들어오는 SSH를 요구하지 않으며, 앱이 Hermes와 VPS로 **아웃바운드 연결**한다.

운영 주의: VPS 점검에서 로그인 오류 응답은 정상적으로 왔지만 이후 일부 비인증 API 요청은 제한 시간 내 응답하지 않았다. 원인은 이번 감사에서 확정하지 않았으며, 서버 배포 시 `ThreadingHTTPServer` 여부와 동시 요청 처리를 반드시 확인한다.

## 4. 로그인, 프로필과 세션

### 4.1 로그인 흐름

1. 사용자가 회사 메일 계정과 비밀번호로 로그인한다.
2. 앱은 중앙 HTTP 클라이언트로 VPS의 `/login`을 호출한다.
3. 서버가 메일 인증을 확인하고 기존 에이전트 표시 정보, 역할·Hermes 프로필, 불투명 세션 토큰을 돌려준다.
4. 앱은 비밀번호를 저장하지 않고 로그인, 이름, 역할, 프로필 라벨과 토큰만 로컬 세션에 보관한다.
5. 서버가 명시한 프로필이 우선이며 역할 기반 매핑은 구버전 호환용 fallback이다.

로그인·에이전트 선택 화면의 이름은 기존 Hermes 프로필과 에이전트 표기를 유지한다. 직원 실명 디렉터리는 프로필 메신저 표시 전용이며 로그인 응답, 팀봇 이름, Hermes 프로필명이나 에이전트 매핑을 변경하지 않는다.

세션 토큰은 워크스페이스, 메신저, 메일 호출에 공통으로 사용한다. 워크스페이스 신원 세션은 해시로 SQLite에 저장되어 서버 재시작 뒤 복구할 수 있다. 메일 자격 증명은 서버 메모리에만 유지하며 기본 TTL은 8시간이다. `cryptography`가 설치된 환경에서는 프로세스 내 임시 Fernet 키로 추가 보호하지만 필수 의존성은 아니다.

로그아웃은 네트워크가 끊겨도 앱의 로컬 세션부터 제거한 뒤 서버 revoke를 시도한다. revoke는 워크스페이스 세션과 메일 세션을 함께 폐기한다. 로그인 만료 오류를 받으면 안내 후 로그인 상태를 정리한다.

### 4.2 연결 표시

앱은 인증 서버 상태를 약 30초마다 확인해 연결, 지연, 오프라인 상태를 표시한다. 연결 실패 시 Tailscale 연결 확인을 안내한다. 이 표시는 인증 VPS 상태이며 Hermes SSH나 Nextcloud WebDAV 각각의 완전한 헬스체크를 뜻하지 않는다.

## 5. AI 팀 채팅과 Hermes 연동

### 5.1 프로필 격리와 실행 방식

로그인한 사용자는 서버가 부여한 Hermes 프로필로 연결된다. 2026-08-08 Hermes 호스트에서 확인한 프로필은 `sales`, `finance`, `planning`, `ai_center`, `oliver`, `support`, `d_support`, `hr`, `viby`, `cs`다. 호스트에서 확인한 버전은 Hermes `0.20.0 (2026.8.3)`, Claude Code `2.1.221`이다.

- Hermes 모델: 대화 ID별 지속 ACP 프로세스를 재사용한다.
- Claude 모델: 요청마다 CLI를 한 번 실행하는 one-shot 경로다.
- Hermes와 Claude 사이 모델 전환, 프로필·설정 변경 시 기존 ACP를 닫고 새 실행 문맥을 만든다.
- 한 대화에는 동시에 하나의 요청만 실행하며 취소 시 원격 프로세스 그룹까지 정리한다.
- ACP 유휴 종료는 30분, 원격 프로세스 최대 수명은 12시간, 메시지 실행 제한은 30분이다.

이 지속 ACP 구조로 로컬 파일 왕복 때마다 새 Hermes 세션이 생기던 문제를 막는다. 기존 대화 기록은 첫 세션 시작 시만 전달하고, 이후에는 같은 ACP 세션이 문맥을 유지한다.

### 5.2 모델과 추론 수준

채팅 입력 하단에서 `모델 → 추론 수준` 순으로 고른다. 현재 모델 계약은 다음과 같다.

| 모델군 | 선택 가능한 추론 수준 |
|---|---|
| Fable 5, Opus 4.8 | low, medium, high, xhigh, max |
| GPT-5.6 Sol, GPT-5.6 Terra | minimal, low, medium, high, xhigh |
| GPT-5.6 Luna | minimal, low, medium, high |
| GPT-5.5 | minimal, low, medium, high, xhigh |

지원하지 않는 값은 `medium`으로 정규화한다. 표시 순서는 높은 수준이 위, 낮은 수준이 아래다.

### 5.3 로컬 파일·명령 브리지

Hermes 서버는 사용자 노트북 파일에 직접 접근하지 않는다. 봇이 구조화된 로컬 작업 요청을 반환하면 Orca 메인 프로세스가 선택한 프로젝트 루트 안에서 실행하고 결과를 같은 대화 세션에 돌려준다.

- 파일: 목록, UTF-8 텍스트 읽기·쓰기. 프로토콜상 삭제는 지원하지 않는다.
- 파일 1개 최대 512KiB, 결과 최대 768KiB, 디렉터리 목록 최대 500개.
- 프로젝트 루트 탈출, 심볼릭 링크 탈출, Git 메타데이터 쓰기를 차단한다.
- SHA-256 예상 리비전으로 동시 수정 충돌을 막고 임시 파일+rename으로 원자적 저장한다.
- 로컬 파일 왕복은 최대 8라운드다.
- 명령은 `shell: false` 직접 실행, 허용된 설치 명령만 사용하며 기본 전경 제한은 120초다.
- 백그라운드 프로세스 실행·중지와 localhost URL 감지를 지원하며 출력은 최대 64KiB다.

앱에는 Electron IPC가 기본 경로이며 `127.0.0.1:47821`의 토큰 보호 loopback 호환 서버도 남아 있다. 포트가 이미 사용 중이면 임시 포트로 물러난다. 이는 외부 네트워크에 공개하지 않는다.

### 5.4 팀 채팅 첨부·기록과 세션 접근

- 한 메시지 최대 5개 텍스트 첨부.
- 허용 확장자: `.txt`, `.md`, `.csv`, `.json`, `.yaml`, `.yml`, `.log`.
- 첨부 1개 최대 96KB이며 전체 텍스트 문맥도 제한한다.
- 클립보드 이미지는 임시 파일로 만든 뒤 원격에 전송하고 턴 종료 후 정리한다.
- 일반 이미지 파일 선택형 첨부는 현재 제공하지 않는다.
- 과거 기록 정규화: 최대 24개 메시지, 메시지당 12,000자, 총 48,000자.

세션 토큰은 프롬프트 원문에 넣지 않고 SSH 표준입력으로 전달해 원격 셸의 `$MAILTOKEN`으로만 노출한다. 이름은 기존 메일 연동에서 유지됐지만 같은 토큰으로 프로필 메신저 API도 호출한다.

봇은 사용자가 대화 내용을 물을 때만 메신저 채널 목록·최근 메시지·검색 API를 온디맨드로 호출한다. 대화를 프롬프트에 자동 주입하지 않으며 원문 대량 인용, 토큰 노출, 무맥락 타인 메시지 노출을 금지한다. 조회된 메시지는 비신뢰 데이터로 취급해 그 안의 명령을 실행하지 않는다. 앱은 팀 채팅 입력창에 세션 동안 메일·메시지 열람 권한이 전달된다는 안내를 표시한다. 이 경로는 저장소에 구현됐지만 VPS API와 Hermes 스킬 배포·실계정 검증은 W3c 대기 상태다.

## 6. 워크스페이스 허브와 Nextcloud 공유

### 6.1 사용자 경험

워크스페이스 허브는 메인 페이지이며 목록 보기와 보드 보기, 상세 패널을 제공한다. 프로젝트 이름 대신 사용자별 로컬 별칭을 정할 수 있고 소유자는 중앙 공유 이름도 바꿀 수 있다. upstream Tasks 사이드바 메뉴는 의도적으로 렌더만 제거했으며 서버·IPC·`TaskPage`와 내부 `openTaskPage()` 경로는 보존한다.

공유 대상은 로컬 Git 저장소와 일반 폴더 워크스페이스다. SSH·원격 저장소는 로컬 파일 업로드 대상으로 선택하지 않는다. GitHub 계정이나 SAMWOO 관리자 GitHub 저장소를 워크스페이스 공유에 사용하지 않는다.

### 6.2 생성과 중앙 저장

사용자가 공유 버튼을 누르면 공유 레코드를 만든 뒤 선택 프로젝트를 즉시 업로드한다. 중앙 경로는 기본적으로 다음과 같다.

```text
SAMWOO-Workspaces/<Hermes 프로필>/<공유 UUID>/
```

프로필이 같은 사용자에게만 공유 목록이 노출된다. 각 사용자 노트북에는 필요할 때 파일을 내려받아 로컬 복제본을 만들며, 중앙 파일을 직접 편집하는 네트워크 드라이브 방식은 아니다.

### 6.3 권한

| 권한 | 목록·읽기·다운로드 | 업로드·수정·삭제 | 보드 상태 변경 |
|---|---:|---:|---:|
| `view` | 불가(메타데이터 보기만) | 불가 | 불가 |
| `download` | 가능 | 불가 | 불가 |
| `contribute` | 가능 | 가능 | 가능 |
| 소유자 | 가능 | 가능 | 가능 |

모든 서버 쿼리는 서버가 토큰에서 결정한 프로필을 사용한다. 클라이언트가 임의로 보낸 프로필은 신뢰하지 않으며, 폐기된 공유와 다른 프로필의 공유 ID는 사용할 수 없다.

### 6.4 동기화와 충돌 처리

- 작업 전에 pull/push 미리보기로 변경 내역을 보여준다.
- 로컬 manifest는 앱 userData의 `samwoo-workspace-sync`에 권한 `0600`으로 저장하고 해시와 ETag를 추적한다.
- 같은 파일이 양쪽에서 바뀌면 `로컬 유지 / 원격 사용 / 둘 다 유지`를 선택한다.
- 둘 다 유지는 `.local-<timestamp>` 사본을 만든다.
- 삭제는 명시적 확인과 일치하는 ETag가 있어야 실행한다.
- 파일 1개 최대 16MiB, 한 번에 업로드 후보 최대 5,000개, 원격 항목 최대 10,000개, 경로 깊이 최대 64다.
- 심볼릭 링크는 제외하고 Windows에서 만들 수 없는 파일명도 차단한다.

기본 제외 디렉터리는 `.aws`, `.git`, `.gnupg`, `.next`, `.ssh`, `.venv`, `__pycache__`, `build`, `coverage`, `dist`, `node_modules`, `out`, `venv`다. `.env` 계열(예제·샘플·템플릿 제외), `.netrc`, `.npmrc`, `.pypirc`, `credentials`, `id_*`, `.key`, `.p12`, `.pem`, `.pfx` 등 자격 증명 가능 파일도 제외한다.

### 6.5 보드·변경 알림·댓글

- 보드 상태는 중앙에 저장되어 다른 사용자의 보드에도 반영된다.
- 상태 변경자와 변경 시각을 기록하되 파일 내용의 `updated_at`과는 분리한다.
- 허브 목록은 60초 주기로 새로 확인하며 마지막으로 본 리비전보다 새로운 경우 변경 배지를 표시한다.
- 공유별 댓글을 작성하고 완료 체크로 처리 여부를 표시한다.
- 댓글은 페이지네이션하며 상세 패널을 펼친 동안 15초마다 갱신한다.
- 댓글 작성자·완료 처리자를 감사 정보로 남긴다. 현재 댓글 수정·삭제는 제공하지 않는다.

공유 해제는 중앙 공유 레코드를 폐기해 사용자 목록에서 숨기는 동작이다. **Nextcloud의 실제 디렉터리와 파일을 자동 영구 삭제하지 않는다.** 개별 파일 삭제 API는 있으며 `contribute` 이상 권한과 ETag 조건을 요구한다.

## 7. 프로필 메신저

### 7.1 현재 사용 가능한 기능

메신저는 사이드바 독립 메뉴에서 전용 팝아웃 창으로 열린다. 창은 한 개만 유지하고 기본 크기는 1040×720, 최소 720×480이며 마지막 위치·크기를 기억한다.

- 같은 프로필의 팀 채널 1개와 활성 워크스페이스별 채널.
- 워크스페이스 허브에서 해당 공유 채널을 바로 열 수 있다.
- 메시지 최대 4,000자, 페이지당 100개, 답장 미리보기, 읽지 않음 개수.
- 한글 IME 조합 중 Enter는 전송으로 처리하지 않는다.
- 다른 프로필·채널의 메시지나 답장을 섞지 않으며 메인 창과 팝아웃 사이 세션 전달도 신뢰된 renderer만 허용한다.
- 메신저 첨부파일은 의도적으로 보류했다. 파일은 워크스페이스로 공유한다.
- 메시지 작성자·답장·채널 미리보기·알림·온라인 목록은 서버 CSV 디렉터리의 직원 표시명을 사용한다. `user-display-names.csv`가 우선이고 누락 시 `role-map.csv`의 `name`, 두 원천 모두 없으면 login 순으로 fallback한다.
- login은 메시지 저장·본인 판정·프로필 격리의 불변 식별자이며 동명이인이 있어도 표시명으로 비교하지 않는다. 실명 표시는 메신저에만 적용하고 기존 Hermes 프로필·에이전트 표기는 유지한다.

앱은 SSE 연결을 우선 사용하고, 연결할 수 없으면 기존 폴링을 그대로 유지한다. 운영 서버의 `/events`가 아직 404이므로 배포 전 실사용 동기화는 현재 **폴링 fallback**이다.

- SSE 연결 시 메시지 이벤트를 즉시 반영하고 열린 메신저·전역 inbox의 확인 폴링은 각각 약 1분·5분으로 낮춘다.
- SSE 미연결 시 열린 메신저는 포그라운드 약 3초·백그라운드 약 30초, 전역 읽지 않음·알림은 약 30초로 폴링한다.
- 첫 폴링은 알림을 띄우지 않고 이후 새 메시지는 OS 알림과 dock/taskbar 배지로 알린다.
- 팝아웃이 포커스된 채널은 중복 OS 알림을 억제한다.
- 화면이 포커스되고 메시지 끝을 보고 있을 때만 새 메시지를 읽음 처리하며 읽음 커서는 뒤로 가지 않는다.

### 7.2 실시간 클라이언트와 서버 확장 기반

서버 코드에는 SQLite WAL, 전역 DB 락 제거, `clientMessageId` 멱등 전송, 프로필별 in-process pub/sub, 메시지·읽음·snapshot·presence 이벤트, 25초 하트비트가 구현되어 있다. 기존 폴링 API는 그대로 유지한다.

앱에는 main 프로세스 단일 SSE 연결, 지수 백오프 재연결, 폴링 fallback, 멱등 전송 큐와 pending·재시도·재전송 UI, `onlineLogins` 상태와 온라인 표시가 구현되어 있다. 연결이 끊기면 잘못된 온라인 상태를 보여주지 않도록 프레즌스 UI를 숨긴다. 서버 이벤트의 `isAuthor`는 수신 사용자의 로그인과 `authorLogin`을 비교해 다시 계산한다.

운영 VPS의 `GET /events`는 아직 404이므로 현재 앱은 자동으로 폴링으로 강등된다. **앱 구현은 완료됐고 서버 배포와 2계정 실측은 W3c 대기 상태**다.

SSE를 배포할 때 서버는 반드시 `ThreadingHTTPServer`여야 한다. 단일 스레드 서버에서 장시간 SSE 연결을 열면 다른 요청을 막는다.

## 8. 회사 메일 연동

### 8.1 연결과 보안

메일은 앱이 직접 IMAP/SMTP 비밀번호를 계속 들고 호출하는 방식이 아니다. 로그인 시 VPS가 자격 증명을 메모리 세션에 연결하고 앱·Hermes는 불투명 토큰만 보낸다.

- IMAP: `play.samwooeleco.com:993`, SSL.
- SMTP: `play.samwooeleco.com:587`, STARTTLS.
- 기본 세션 TTL 8시간, 네트워크 제한 20초.
- 받은메일 목록 최대 50개.
- 발송 수신자 최대 20명, 본문 최대 256KiB.
- 발신자는 로그인한 메일함으로 고정한다.
- Hermes 메일 스킬은 발송 전에 사용자에게 수신자·제목·내용 확인을 받는다.

지원 API는 `/mail/list`, `/mail/read`, `/mail/send`, `/mail/attachments/list`, `/mail/attachments/save-to-workspace`다. 앱은 풀 메일 클라이언트 화면을 제공하지 않으며 주 사용 경로는 Hermes 팀봇의 메일 스킬이다.

### 8.2 첨부파일 처리

메일 읽기는 본문과 첨부 메타데이터만 반환한다. 첨부 저장은 VPS가 IMAP에서 바이너리를 읽어 Nextcloud 워크스페이스로 직접 전송하므로 바이너리가 봇 프롬프트나 사용자 앱을 통과하지 않는다.

- RFC2047·RFC2231·EUC-KR 파일명과 inline filename을 처리한다.
- 저장 가능한 첨부 1개 최대 16MiB.
- 같은 세션의 메일 소유자와 같은 프로필의 워크스페이스 쓰기 권한을 모두 확인한다.
- 기본 저장 위치는 워크스페이스의 `mail/<파일명>`이다.
- 같은 이름이 있으면 덮어쓰지 않고 `(2)` 형식으로 새 이름을 만든다.
- 저장 후 워크스페이스 리비전을 갱신해 다른 사용자에게 변경을 알린다.

메일 첨부 파이프라인은 저장소에 **구현 완료** 상태지만 VPS 모듈 반영과 실제 계정 통합 시험은 이번 감사에서 확인되지 않았다. 따라서 운영 기능으로 단정하지 않는다.

## 9. VPS 서버와 데이터 저장

서버는 `/opt/samwoo-auth` 배포를 기준으로 하는 Python 서비스다. 현재 운영 응답에서 Python `3.12.3`을 확인했다. 핵심 인증·워크스페이스·메신저 경로는 Python 표준 라이브러리와 SQLite를 사용하며 메일 메모리 보호용 `cryptography`는 선택 사항이다.

| 저장 대상 | 위치·방식 |
|---|---|
| 워크스페이스 세션·공유·댓글 | SQLite `/opt/samwoo-auth/workspace-shares.db` |
| 프로필 메시지·읽음 커서 | 같은 SQLite DB |
| 메신저 직원 표시명·프로필 멤버 | VPS 런타임 CSV (`user-display-names.csv` 우선, `role-map.csv` fallback), 저장소 커밋 금지 |
| 공유 파일 | Nextcloud WebDAV |
| 메일 비밀번호 | 서버 프로세스 메모리, TTL 만료·revoke 시 폐기 |
| 로컬 동기화 manifest | 각 노트북 Electron userData, 권한 `0600` |

SQLite는 WAL, `busy_timeout=5000`, `synchronous=NORMAL`, foreign keys를 사용한다. 테이블은 `workspace_sessions`, `workspace_shares`, 댓글, `profile_messages`, `profile_message_reads`이며 기존 데이터를 파괴하지 않는 `CREATE TABLE IF NOT EXISTS`/추가 마이그레이션 방식이다.

온라인 SQLite backup API를 쓰는 `backup-workspace-db.sh`와 14일 보관 정책이 구현되어 있다. 운영 cron 등록 여부는 미확인이다. SSE 이벤트 버스는 단일 프로세스 메모리 기반이므로 현재 단일 서버 구성을 전제로 한다.

프로필 멤버 API는 Bearer 토큰의 서버 세션에서 프로필을 결정하며 클라이언트가 조회 프로필을 선택할 수 없다. CSV는 mtime 변경 시 재로딩하고 읽기 실패 시 login 표시로 기능 저하한다. 이 디렉터리는 메신저 전용으로 에이전트·Hermes 프로필 명칭에는 관여하지 않는다.

## 10. 업데이트, 빌드와 사내 설치

### 10.1 빌드·공개 절차

`.github/workflows/build-samwoo-windows.yml`은 수동 실행만 허용한다.

1. 관리자가 upstream 변경과 SAMWOO 변경을 검증한다.
2. GitHub Actions의 Windows 2022 runner에서 의존성 설치, 지정 통합 테스트, 전체 Python 서버 테스트를 실행한다.
3. Windows 앱을 빌드하고 사내 인증서로 서명한다.
4. 인증서 해시·publisher·서명과 `latest.yml`·blockmap·버전 일치를 검증한다.
5. GitHub에는 **Draft 릴리스**로 만든다.
6. 관리자가 산출물과 해시를 확인한 뒤 Public release로 공개한다.

Windows NSIS 설치기는 one-click이 아닌 설치 마법사 방식이며 설치 경로 변경과 바탕화면 바로가기를 지원하고 설치 직후 자동 실행은 하지 않는다. 산출물 이름은 `samwoo-orca-windows-setup.exe`다.

### 10.2 설치된 앱의 업데이트

앱은 공개 GitHub release의 `latest.yml`을 확인한다. 자동 점검은 대략 하루 주기이며 공개 직후 파일 전파가 불완전한 경우 약 1시간 뒤 재시도한다.

사용자가 업데이트 버튼을 누르면 앱이 설치 파일과 blockmap을 다운로드하고 단계·진행률을 표시한다. Windows에서는 진행 표시 프로세스를 앱 종료 뒤에도 유지해 무인 설치하고 SAMWOO-ORCA를 다시 실행한다. 앱이 닫히지 않을 때를 위한 약 20초 watchdog이 있다.

내부 인증서 설치, 설치 파일 해시·서명 검증, Tailscale 설정, OpenSSH Client 준비와 인바운드 SSH 차단은 사내 설치 키트의 계약이다. 실제 키·비밀번호는 저장소에 두지 않는다. Nextcloud 설치 키트의 마지막 업로드 상태는 이번 감사에서 재확인하지 않았으므로 별도 운영 확인이 필요하다.

## 11. upstream Orca에서 유지하는 기능

SAMWOO 커스텀 기능은 upstream 기능을 대체하지 않고 추가한다. 다음 기반 기능을 유지한다.

- 여러 CLI 에이전트를 나란히 실행하고 Git worktree별로 격리·비교·병합.
- 분할 터미널, 재시작 후 scrollback, 에이전트 상태·알림.
- 파일 탐색기·편집기, Markdown·이미지·PDF 미리보기, 파일·이미지의 에이전트 전달.
- 내장 Chromium 브라우저, Design Mode, 브라우저 자동화·computer use.
- Git 변경·diff 검토·주석·commit·branch·worktree 관리.
- GitHub·GitLab 등 provider별 소스 제어 경로와 Linear 등 upstream 연동.
- SSH worktree, 원격 파일·터미널·Git, 포트 포워딩·재연결, Windows WSL 실행.
- 빠른 열기, 계정 전환·사용량 표시, skills·plugins·MCP, Orca CLI와 자동화.

의도적 차이는 Tasks 사이드바 렌더 제거뿐이며 내부 구현을 삭제하지 않았다. SAMWOO 워크스페이스 공유는 GitHub 기능과 독립적이므로 사용자가 GitHub 계정 없이도 동작한다.

## 15. 현재 대기열

작업 대기열과 웨이브별 실행 상태는 [WAVES.md](./WAVES.md)에서 관리한다. 이 문서는 제품 결정·아키텍처·상태·기준만 다룬다.

## 16. 검증·배포 게이트

- Tasks 탭 접근 제거는 의도된 변경이며 회귀가 아니다.
- 각 기능 단계는 지시서의 focused test, TypeScript 검사, oxlint, max-lines ratchet, i18n coverage를 통과해야 한다.
- 서버 변경은 기존 폴링 API와 구버전 앱을 깨지 않아야 하며 마이그레이션은 기존 데이터를 보존해야 한다.
- SSE 배포 전 `ThreadingHTTPServer`와 동시 요청 시험은 0순위다.
- Git 변경은 native·WSL·SSH별 Git 2.25 baseline과 GitHub 외 provider를 고려한다.
- UI는 `docs/STYLEGUIDE.md`, `main.css` 토큰과 기존 shadcn primitive를 따른다.
- lint disable이나 per-file max-lines 예외로 게이트를 우회하지 않는다.
- 빌드·배포는 사용자의 명시적 지시가 있을 때만 실행한다.

## 17. 현재 알려진 운영 차이와 위험

1. 서버와 앱의 SSE 경로는 구현됐지만 운영 `/events`가 404라 현재 앱은 폴링 fallback으로 동작한다. 서버 배포와 2계정 실측이 필요하다.
2. `clientMessageId` 기반 renderer 전송 큐·pending·자동 재시도·수동 재전송은 앱 구현 완료 상태이며, 배포·실측 대기다.
3. `onlineLogins` 상태 저장과 프레즌스 UI는 앱 구현 완료 상태이며, 운영 SSE 배포·2계정 실측 전까지 연결이 없어 표시되지 않는다.
4. 메일 첨부 파이프라인은 코드에 있으나 VPS 반영과 실계정 통합 시험이 확인되지 않았다.
5. 봇용 메시지 검색 API와 Hermes 스킬은 구현됐지만 VPS·Hermes 통합 배포와 실계정 요약·타 프로필 차단 실측은 W3c 대기다.
6. VPS가 ThreadingHTTPServer인지 이번 감사로 확인하지 못했다. SSE 운영 전 반드시 확인해야 한다.
7. 인증 VPS의 일부 연속 요청에서 타임아웃을 관측했다. 배포 전 동시성·응답성 실측이 필요하다.
8. 백업 스크립트는 구현됐지만 운영 cron 등록 여부는 미확인이다.
9. Nextcloud 사내 설치 키트의 최신 업로드 상태는 이번 감사에서 확인하지 않았다.
10. 메신저 실명 디렉터리와 멤버 API는 구현됐지만 VPS CSV 형식·핫 리로드·2계정 프로필 격리 실측은 W3c 대기다.

## 18. 공통 금지 사항

- `max-lines` disable·예외 추가 금지.
- STYLEGUIDE에 없는 색상, 폰트 크기, 그림자 tier 임의 추가 금지.
- `deploy/install.ps1` 열람·출력·커밋 금지.
- 사용자 변경의 임의 reset·revert 금지.
- 봇 프롬프트에 대화·메일 원문이나 자격 증명 상시 주입 금지.
- 공개 저장소에 비밀번호, 토큰, Tailscale enrollment key, 인증서 개인키를 기록하지 않는다.
- 운영 확인 없이 `구현 완료`를 `배포 완료`로 표현하지 않는다.
