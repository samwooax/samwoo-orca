## 1. 제품 정의와 지원 범위

SAMWOO-ORCA는 upstream Orca 데스크톱 앱을 기반으로 다음을 결합한 사내 협업 도구다.

- Nextcloud 기반 팀 워크스페이스와 파일 동기화
- Hermes·Claude·GPT 계열 모델을 사용하는 프로필별 AI 팀 채팅
- 프로필별 팀·워크스페이스 메신저와 알림
- 회사 메일 IMAP/SMTP 연동 및 메일 첨부파일의 워크스페이스 직행 저장
- upstream Orca의 에이전트, Git worktree, 터미널, 편집기, 브라우저, SSH·WSL 실행 기능
- Windows 사내 설치·자동 업데이트 경로

주 사용자는 비개발 직원을 포함한 사내 사용자이며 목표 동시 접속 규모는 약 100명이다. 중앙 API와 공유 데이터는 프로필 단위로 격리한다. 확장 트리거는 동시 사용자 300명 이상 또는 SQLite 단일 VPS의 실측 병목이며, 그 전에는 Redis·Kafka·클러스터를 도입하지 않는다.

SAMWOO 회사 배포의 기준 플랫폼은 Windows다. upstream 코드의 macOS·Linux·Windows, WSL, SSH 호환성은 유지하며 SAMWOO 전용 코드는 특정 로컬 OS나 경로 구분자를 가정하지 않는다.

Tailscale MagicDNS는 관리 Windows PC에서 해석 실패한 이력이 있어 현재는 IP를 직접 쓴다. 엔드포인트는 `src/shared/samwoo-service-endpoints.ts`에서 중앙 관리한다. 클라이언트 노트북에 외부에서 들어오는 SSH를 요구하지 않으며, 앱이 Hermes와 VPS로 **아웃바운드 연결**한다.

운영 이력: 배포 전 점검에서 일부 연속 API 요청이 제한 시간 내 응답하지 않는 현상이 있었다. 원인은 구 서버 코드의 전역 DB 락이었고, 2026-08-09 WAL 전환·락 제거 배포 후 연속 10회 요청이 모두 약 0.5~1ms에 응답해 해소를 확인했다. 서버는 `ThreadingHTTPServer`를 사용한다(소스 확인).

## 4. 로그인, 프로필과 세션

### 4.1 로그인 흐름

1. 사용자가 회사 메일 계정과 비밀번호로 로그인한다.
2. 앱은 중앙 HTTP 클라이언트로 VPS의 `/login`을 호출한다.
3. 서버가 메일 인증을 확인하고 기존 에이전트 표시 정보, 역할·Hermes 프로필, 불투명 세션 토큰을 돌려준다.
4. 앱은 비밀번호를 저장하지 않고 로그인, 이름, 역할, 프로필 라벨과 토큰만 로컬 세션에 보관한다.
5. 서버가 명시한 프로필이 우선이며 역할 기반 매핑은 구버전 호환용 fallback이다.

로그인 식별자의 정규 형태는 **도메인을 제외한 소문자 아이디**다. 예를 들어 메일 주소로 로그인해도 서버 세션·메시지·프레즌스·워크스페이스 담당자에는 `user` 형태를 사용한다. 서버는 세션 결합·복원 시, 앱은 로그인 응답 저장·localStorage 복원 시 같은 규칙을 적용한다. 실명은 표시값일 뿐 식별자로 사용하지 않는다.

로그인·에이전트 선택 화면의 이름은 기존 Hermes 프로필과 에이전트 표기를 유지한다. 직원 실명 디렉터리는 프로필 메신저와 워크스페이스 협업 UI의 사용자 표시에만 쓰며 로그인 응답, 팀봇 이름, Hermes 프로필명이나 에이전트 매핑을 변경하지 않는다.

세션 토큰은 워크스페이스, 메신저, 메일 호출에 공통으로 사용한다. 워크스페이스 신원 세션은 해시로 SQLite에 저장되어 서버 재시작 뒤 복구할 수 있다. 메일 자격 증명은 서버 메모리에만 유지하며 기본 TTL은 8시간이다. `cryptography`가 설치된 환경에서는 프로세스 내 임시 Fernet 키로 추가 보호하지만 필수 의존성은 아니다.

로그아웃은 네트워크가 끊겨도 앱의 로컬 세션부터 제거한 뒤 서버 revoke를 시도한다. revoke는 워크스페이스 세션과 메일 세션을 함께 폐기한다. 로그인 만료 오류를 받으면 안내 후 로그인 상태를 정리한다.

### 4.2 연결 표시

앱은 인증 서버 상태를 약 30초마다 확인하고, 각 Hermes 프로필 채팅 탭 이름 왼쪽의 상태 점으로 연결·확인 중·오프라인을 표시한다. 상태 점의 Tooltip은 지연 시간 또는 Tailscale 연결 확인 안내를 제공한다. 이 표시는 인증 VPS 상태이며 Hermes SSH나 Nextcloud WebDAV 각각의 완전한 헬스체크를 뜻하지 않는다.

## 5. AI 팀 채팅과 Hermes 연동

### 5.1 프로필 격리와 실행 방식

로그인한 사용자는 서버가 부여한 Hermes 프로필로 연결된다. 2026-08-09 Hermes 호스트에서 확인한 프로필은 `default`, `ai_center`, `cs`, `d_support`, `finance`, `hr`, `oliver`, `planning`, `sales`, `support`, `viby`다. 앱의 새 채팅 탭과 복원된 채팅 탭은 원시 프로필 ID 대신 표시명 매핑을 사용한다. 현재 매핑은 `default`→기본, `ai_center`→AI 센터, `cs`→CS, `d_support`→대구영업지원, `finance`→재경, `hr`→총무인사, `oliver`→전략기획, `planning`→영업기획, `sales`→영업, `support`→영업지원이며 미등록 프로필은 원시 ID를 그대로 표시한다. 이 매핑은 앱 표시에만 사용하며 서버 프로필 식별자는 변경하지 않는다. 호스트에서 확인한 버전은 Hermes `0.20.0 (2026.8.3)`, Claude Code `2.1.221`이다.

- Hermes 모델: 대화 ID별 지속 ACP 프로세스를 재사용한다.
- Claude 모델: 요청마다 CLI를 한 번 실행하는 one-shot 경로다.
- Hermes와 Claude 사이 모델 전환, 프로필·설정 변경 시 기존 ACP를 닫고 새 실행 문맥을 만든다.
- 한 대화에는 동시에 하나의 요청만 실행하며 취소 시 원격 프로세스 그룹까지 정리한다.
- ACP 유휴 종료는 30분, 원격 프로세스 최대 수명은 12시간, 메시지 실행 제한은 30분이다.

이 지속 ACP 구조로 로컬 파일 왕복 때마다 새 Hermes 세션이 생기던 문제를 막는다. 기존 대화 기록은 첫 세션 시작 시만 전달하고, 이후에는 같은 ACP 세션이 문맥을 유지한다.

### 5.3 로컬 파일·문서·명령 브리지

Hermes 서버는 사용자 노트북 파일에 직접 접근하지 않는다. 봇이 구조화된 로컬 작업 요청을 반환하면 Orca 메인 프로세스가 선택한 프로젝트 루트 안에서 실행하고 결과를 같은 대화 세션에 돌려준다.

- 파일: 목록, UTF-8 텍스트 읽기·쓰기. 프로토콜상 삭제는 지원하지 않는다.
- 파일 1개 최대 512KiB, 결과 최대 768KiB, 디렉터리 목록 최대 500개.
- 프로젝트 루트 탈출, 심볼릭 링크 탈출, Git 메타데이터 쓰기를 차단한다.
- SHA-256 예상 리비전으로 동시 수정 충돌을 막고 임시 파일+rename으로 원자적 저장한다.
- 로컬 파일 왕복은 최대 8라운드다.
- 명령은 `shell: false` 직접 실행, 허용된 설치 명령만 사용하며 기본 전경 제한은 120초다.
- 백그라운드 프로세스 실행·중지와 localhost URL 감지를 지원하며 출력은 최대 64KiB다.
- 문서: PDF text layer, XLSX 문자열·숫자·boolean·날짜·오류·수식 셀, PPTX 텍스트 문단을 별도 worker에서 확인·분할 추출한다. 일반 UTF-8 파일 제한을 넓히지 않는다.
- 문서 입력은 파일당 64MiB다. PDF는 최대 1,000페이지·호출당 10페이지, XLSX/PPTX는 호출당 200개 셀/문단을 반환한다.
- XLSX inspect/extract는 bundled frozen worker가 있는 host에서 openpyxl read-only 스트리밍으로 실행해, ERP 내보내기류 대형 워크북(실측 182만 셀·시트 XML 66MB)도 파일 분할 없이 200셀 창으로 나눠 읽는다. 스캔 상한은 800만 셀이며 worker가 없으면 기존 in-process parser(XML당 16MiB)로 동작한다. 번역 적용 경로는 기존 in-process 한도를 유지한다.
- XLSX 번역 적용은 호출당 128셀, 추출 원문과 원본 SHA-256 일치를 요구한다. 수식·숫자·style·chart·media는 유지하고 원본이 아닌 신규 `.xlsx` project path에 저장한다.
- PPTX 번역도 최대 128문단과 원문·SHA-256 일치를 요구하며 run formatting·도형·chart·media를 유지한 신규 `.pptx`에 저장한다.
- 직접 고른 PDF/XLSX/PPTX는 main private store의 opaque artifact ID로 관리하고 conversation 소유권과 request 배타 결합을 검증한 `@attachments/...` 경로로만 모델에 보인다. 같은 대화에서 첨부 chip을 유지하는 동안 후속 요청이 재사용할 수 있고, project 파일은 local worktree/folder root authority를 그대로 적용한다.
- local project가 없는 직접 첨부 XLSX/PPTX 번역은 native save dialog로 사용자가 신규 저장 위치를 승인한다.
- Excel Artifact v1은 verified bundled worker가 있는 Windows local host에서 workbook 생성·일반 수정·구조 검증을 제공한다. 수식, named range, 표, autofilter, freeze pane, 병합, style, 조건부서식, data validation, native chart, 이미지와 page setup을 Workbook Spec으로 선언한다.
- PPTX는 슬라이드·텍스트·도형·표·차트·이미지 생성과 텍스트/슬라이드/표 편집을 제공한다. PDF는 페이지별 text element를 top-left inch 좌표로 배치한 신규 문서를 만들고 페이지 삭제·재배열·회전·병합·watermark·metadata 편집을 제공한다. 생성 성공은 PDF 재개방, 페이지 수, 페이지별 text layer와 양수 `textCharacterCount`까지 확인해야 한다.
- Python 3.13과 문서 engine은 Windows 설치본에 포함하며 사용자는 Python, pip, LibreOffice 또는 별도 package를 설치하지 않는다. capability는 main의 bundle integrity·engine probe가 성공할 때만 모델에 제공한다.
- Electron과 frozen Python worker 사이의 JSONL은 UTF-8로 고정한다. worker staging은 사용자 파일명과 분리된 ASCII 이름이며 main이 성공·실패 모두 정리한 뒤 검증된 최종 파일만 원자적으로 commit한다.
- 스캔 PDF OCR, 기존 PDF 본문의 무손실 임의 치환, LibreOffice 시각 preview, 매크로·ActiveX·OLE·전자서명 보존은 지원하지 않고 원본을 변경하지 않은 채 명시적으로 실패한다.

문서 브리지는 `samwoo/upstream-v1.4.168`의 `v1.4.204` 공개 릴리스(2026-08-16)까지 통합·배포됐다. envelope JSON 파싱이 실패하면 main이 결정적으로 교정한다: 완전한 JSON 값 뒤에 닫는 delimiter만 꼬리로 붙은 경우 값은 그대로 두고 꼬리만 버리고, 내부 결함은 닫는 delimiter 정확히 한 개를 삭제하는 후보 중 스칼라 토큰이 접합될 수 없는 위치만 고려해 파싱 가능한 복원 결과가 유일할 때만 채택한다. 다의적이거나 잘린 JSON은 교정하지 않고, 문자열·값·필드는 바꾸지 않으며, 교정 후에도 기존 schema 검증을 통과해야 실행한다. host가 교정하지 못한 malformed envelope는 operation 실행 전 같은 모델 세션에 최대 두 번 교정을 요청한다. PDF text element는 지정 크기에서 넘칠 때 6pt까지 원래 비율로 자동 축소한다. Excel create는 정확한 v1 필드 예시(차트 canonical 형식·anchor `position` 포함)를 모델에 제공하고, `overwrite` 누락과 관측된 column/row/autofilter/validation/chart(`chartType`→`type`, 공유 `categories` 배분, series `{sheet,range}`→`values`) 별칭만 충돌 없이 정규화한 뒤 동일한 worker schema·semantic validation을 적용한다. `formula.references` 검증은 openpyxl Tokenizer의 RANGE operand로 시트 참조를 추출해 `=SUM(시트!범위)` 류 오탐을 제거하고, 실패 시 오탈 참조 셀 주소와 casefold 중복 제거된 누락 시트명 상위 5개를 각 항목 절단·전체 상한 안에서 반환한다. 차트 create는 선언된 픽셀 width/height를 실제 렌더 크기에 적용한다. worker schema 오류는 실패 경로와 그 지점의 기대 형태(허용 key·타입·enum·pattern)를 함께 반환하고, `fill` 색 문자열·freezePane 셀 주소 별칭은 main이 정규화한다. 표·named range 이름은 Excel과 동일하게 한글 등 유니코드 문자를 허용하되 TRUE/FALSE·R/C·셀 주소형(전각 숫자·RC 표기 포함) 예약 이름은 조기 거부하고, 표의 중복 열 이름과 병합 범위 안 anchor 아닌 셀의 내용(값·수식·hyperlink·comment) 선언도 spec 단계에서 정확한 사유로 거부한다. modify에서 기존 병합 내부 셀은 서식만 허용하고 값 기록은 정밀 오류로 거부한다. 설치본 GUI 실측 전에는 배포 완료로 간주하지 않는다.

앱에는 Electron IPC가 기본 경로이며 `127.0.0.1:47821`의 토큰 보호 loopback 호환 서버도 남아 있다. 포트가 이미 사용 중이면 임시 포트로 물러난다. 이는 외부 네트워크에 공개하지 않는다.

### 5.4 팀 채팅 첨부·기록과 세션 접근

- 한 메시지 최대 5개 첨부.
- 텍스트 허용 확장자는 `.txt`, `.md`, `.csv`, `.json`, `.yaml`, `.yml`, `.log`이며 1개 최대 96KB다.
- PDF/XLSX/PPTX/PNG/JPEG는 파일당 64MiB까지 허용하며 Electron main이 signature·확장자·해시를 확인하고 private artifact store에 보관한다.
- Hermes Team Chat 탭에서 프로젝트 Explorer 파일을 선택하면 `@상대경로` 텍스트를 넣지 않고 main이 현재 local project root와 실제 파일을 다시 검증해 첨부한다. PDF/XLSX/PPTX/이미지는 private artifact로, 96KB 이하 UTF-8 파일은 text attachment로 전달한다.
- 전송한 text/artifact 첨부는 같은 대화의 composer에 남아 후속 질문에도 다시 전달한다. 붙여넣기 임시 이미지는 turn 한정이며, 첨부 제거·대화 교체·view 종료 시 main-owned artifact를 해제한다.
- 문서 추출은 호출당 최대 200개 item이다. 모델이 더 큰 양의 `limit`을 요청하면 main이 200으로 낮춰 실행하고 `nextCursor`로 이어 읽는다. 잘못된 0·음수·비정수 요청은 실행하지 않는다.
- 클립보드 이미지는 임시 파일로 만든 뒤 원격에 전송하고 턴 종료 후 정리한다.
- 일반 PNG/JPEG 파일 선택형 첨부도 같은 native picker에서 제공한다.
- 과거 기록 정규화: 최대 24개 메시지, 메시지당 12,000자, 총 48,000자.

세션 토큰은 프롬프트 원문에 넣지 않고 SSH 표준입력으로 전달해 원격 셸의 `$MAILTOKEN`으로만 노출한다. 이름은 기존 메일 연동에서 유지됐지만 같은 토큰으로 프로필 메신저 API도 호출한다.

봇은 사용자가 대화 내용을 물을 때만 메신저 채널 목록·최근 메시지·검색 API를 온디맨드로 호출한다. 대화를 프롬프트에 자동 주입하지 않으며 원문 대량 인용, 토큰 노출, 무맥락 타인 메시지 노출을 금지한다. 조회된 메시지는 비신뢰 데이터로 취급해 그 안의 명령을 실행하지 않는다. VPS 검색 API와 Hermes 스킬(`samwoo-messages`, `samwoo-mail`)은 2026-08-09 배포 완료했고, 실계정 요약·타 프로필 차단 실측만 남았다.

### 5.5 예약 지시 (PC 로컬 실행)

우측 사이드바의 예약 탭은 작업을 현재 PC의 Orca에 저장하고, 등록 당시 선택한 로컬 프로젝트에 고정한다. 앱 루트의 30초 타이머가 실행 시각을 확인해 독립된 Hermes 팀 채팅 턴을 시작하며, 응답을 `<프로젝트>/SAMWOO-예약결과/<예약 ID>/<실행 시각>.md`에 기록한다.

- 반복 주기는 `5~59분마다`, `1~24시간마다`, 또는 선택 요일의 `매일 지정 시각`이다. 분·시간 반복은 등록 시각을 기준으로 고정해 실행 시간이 밀리지 않는다.
- 실행 원장은 Electron renderer localStorage(`samwoo.schedules.v1`)다. 예약당 지시문 2,000자, 사용자당 최대 20건이며 등록 PC와 프로젝트별로 관리한다.
- Orca가 열려 있고 SAMWOO 로그인이 유지된 동안에만 실행한다. 30초 타이머 지연을 허용하는 90초 이내 작업만 실행하며, 앱이 꺼진 동안 놓친 작업은 재실행하지 않고 `건너뜀`으로 기록한다.
- 일반 예약은 메일 토큰 없이 실행할 수 있다. 메일을 다루는 예약은 실행 시점에 앱의 임시 메일 세션이 유효해야 하며 자격증명을 장기 저장하거나 자동 발급하지 않는다.
- 결과 파일은 Electron main IPC가 선택 프로젝트 권한을 다시 확인한 뒤 새 파일로만 쓴다. 같은 실행 ID의 결과를 덮어쓰지 않으며 저장 실패도 예약 실패로 표시한다.
- SSH·원격 프로젝트는 노트북 로컬 결과 경로로 쓸 수 없으므로 등록 대상에서 제외한다. 팀 봇은 예약에 저장된 로컬 프로젝트 경로를 작업 경로로 전달받는다.
- 기존 버전에서 서버 Hermes Cron에 등록된 예약은 연결 시 원격 작업을 먼저 삭제한 뒤 로컬 실행으로 전환한다. 삭제가 확인되기 전에는 로컬 실행·수정·삭제를 막아 중복 실행과 원격 고아 작업을 방지한다.

## 6. 워크스페이스 허브와 Nextcloud 공유

### 6.1 사용자 경험

워크스페이스 허브는 메인 페이지이며 목록 보기와 보드 보기, 상세 패널을 제공한다. 상단의 반복 설명은 생략하고 목록·보드 전환, 새로고침, 새 공유를 24px 도구 버튼으로 제공한다. 프로젝트 이름 대신 사용자별 로컬 별칭을 정할 수 있고 소유자는 중앙 공유 이름도 바꿀 수 있다. upstream Tasks 사이드바 메뉴는 의도적으로 렌더만 제거했으며 서버·IPC·`TaskPage`와 내부 `openTaskPage()` 경로는 보존한다.

허브가 열린 상태에서 사이드바 프로젝트를 선택하면 기존 활성 프로젝트를 다시 선택한 경우에도 허브를 닫고 그 프로젝트에서 마지막으로 사용하던 터미널·브라우저·편집기 탭으로 복귀한다. Git 프로젝트와 일반 폴더 워크스페이스에 같은 규칙을 적용한다.

공유 대상은 로컬 Git 저장소와 일반 폴더 워크스페이스다. SSH·원격 저장소는 로컬 파일 업로드 대상으로 선택하지 않는다. GitHub 계정이나 SAMWOO 관리자 GitHub 저장소를 워크스페이스 공유에 사용하지 않는다.

### 6.2 생성과 중앙 저장

사용자가 공유 버튼을 누르면 공유 레코드를 만든 뒤 선택 프로젝트를 즉시 업로드한다. 중앙 경로는 기본적으로 다음과 같다.

```text
SAMWOO-Workspaces/<Hermes 프로필>/<공유 UUID>/
```

프로필이 같은 사용자에게만 공유 목록이 노출된다. 각 사용자 노트북에는 필요할 때 파일을 내려받아 로컬 복제본을 만들며, 중앙 파일을 직접 편집하는 네트워크 드라이브 방식은 아니다.

| ------------ | ----------------------: | ---------------: | -------------------------------------: |

모든 서버 쿼리는 서버가 토큰에서 결정한 프로필을 사용한다. 클라이언트가 임의로 보낸 프로필은 신뢰하지 않으며, 폐기된 공유와 다른 프로필의 공유 ID는 사용할 수 없다.

### 6.4 동기화와 충돌 처리

- 작업 전에 pull/push 미리보기로 변경 내역을 보여준다.
- 로컬 manifest는 앱 userData의 `samwoo-workspace-sync`에 권한 `0600`으로 저장하고 해시와 ETag를 추적한다.
- 같은 파일이 양쪽에서 바뀌면 `로컬 유지 / 원격 사용 / 둘 다 유지`를 선택한다.
- 둘 다 유지는 `.local-<timestamp>` 사본을 만든다.
- 삭제는 명시적 확인과 일치하는 ETag가 있어야 실행한다.
- 파일 1개 최대 16MiB, 한 번에 업로드 후보 최대 5,000개, 원격 항목 최대 10,000개, 경로 깊이 최대 64다.
- 심볼릭 링크는 제외하고 Windows에서 만들 수 없는 파일명도 차단한다.

기본 제외 디렉터리는 `.aws`, `.git`, `.gnupg`, `.next`, `.ssh`, `.venv`, `__pycache__`, `build`, `coverage`, `dist`, `node_modules`, `out`, `venv`다. `.env` 계열(예제·샘플·템플릿 제외), `.netrc`, `.npmrc`, `.pypirc`, `credentials`, `id_*`, `.key`, `.p12`, `.pem`, `.pfx` 등 자격 증명 가능 파일도 제외한다.

### 6.5 보드·변경 알림·댓글

- 보드 상태는 중앙에 저장되어 다른 사용자의 보드에도 반영된다.
- 상태 변경자와 변경 시각을 기록하되 파일 내용의 `updated_at`과는 분리한다.
- 담당자는 같은 Hermes 프로필의 멤버만 복수 지정할 수 있고, 변경자·변경 시각을 중앙에 별도로 기록한다.
- 담당자 선택 팝오버는 프로필 멤버 API를 사용하며 목록과 상세 패널에서 동일한 선택 UI를 재사용한다. 담당자, 상태·마감일·담당자 변경자, 댓글 작성자·완료 처리자는 CSV 직원명으로 표시한다. 저장·권한 판정은 계속 login을 사용한다.
- 새 담당자로 지정되면 SSE 이벤트로 OS 알림, 워크스페이스 메뉴 배지와 Dock/작업표시줄 배지를 표시한다. 같은 공유의 중복 이벤트는 한 건으로 세고 허브를 열면 확인 처리한다.
- 마감일은 중앙 공유 메타데이터에 `YYYY-MM-DD`로 저장하고 변경자·변경 시각을 별도로 기록한다. 소유자와 기여자가 상세 패널에서 지정·해제할 수 있으며 목록과 보드에는 동일한 날짜가 표시되고 지난 날짜는 강조한다.
- 작업 항목은 공유별 중앙 테이블에 저장하고 소유자·기여자가 생성하거나 완료 상태를 바꿀 수 있다. 항목별 담당자는 같은 Hermes 프로필의 login 1명만 지정·해제할 수 있으며, 상세 패널은 15초마다 백그라운드 갱신하고 목록·보드에는 `완료/전체` 진행률을 표시한다.
- 허브 목록은 60초 주기로 새로 확인하며 마지막으로 본 리비전보다 새로운 경우 변경 배지를 표시한다.
- 공유별 댓글을 작성하고 완료 체크로 처리 여부를 표시한다.
- 댓글은 페이지네이션하며 상세 패널을 펼친 동안 15초마다 갱신한다.
- 댓글 작성자·완료 처리자를 감사 정보로 남긴다. 현재 댓글 수정·삭제는 제공하지 않는다.

공유 해제는 중앙 공유 레코드를 폐기해 사용자 목록에서 숨기는 동작이다. **Nextcloud의 실제 디렉터리와 파일을 자동 영구 삭제하지 않는다.** 개별 파일 삭제 API는 있으며 `contribute` 이상 권한과 ETag 조건을 요구한다.

## 7. 프로필 메신저

### 7.1 현재 사용 가능한 기능

메신저는 사이드바 독립 메뉴에서 전용 팝아웃 창으로 열린다. 창은 한 개만 유지하고 기본 크기는 1040×720, 최소 720×480이며 마지막 위치·크기를 기억한다.

- 같은 프로필의 팀 채널 1개와 활성 워크스페이스별 채널.
- 워크스페이스 허브에서 해당 공유 채널을 바로 열 수 있다.
- 메시지 최대 4,000자, 페이지당 100개, 답장 미리보기, 읽지 않음 개수.
- 한글 IME 조합 중 Enter는 전송으로 처리하지 않는다.
- 다른 프로필·채널의 메시지나 답장을 섞지 않으며 메인 창과 팝아웃 사이 세션 전달도 신뢰된 renderer만 허용한다.
- 메신저 첨부파일은 의도적으로 보류했다. 파일은 워크스페이스로 공유한다.
- 메시지 작성자·답장·채널 미리보기·알림·온라인 목록과 워크스페이스 협업 사용자 표시는 서버 CSV 디렉터리의 직원 표시명을 사용한다. `user-display-names.csv`가 우선이고 누락 시 `role-map.csv`의 `name`, 두 원천 모두 없으면 login 순으로 fallback한다.
- login은 메시지 저장·본인 판정·프로필 격리의 불변 식별자이며 동명이인이 있어도 표시명으로 비교하지 않는다. 실명 표시는 메신저와 워크스페이스 협업 UI에만 적용하고 기존 Hermes 프로필·에이전트 표기는 유지한다.

앱은 SSE 연결을 우선 사용하고, 연결할 수 없으면 기존 폴링을 그대로 유지한다. 운영 서버의 `/events`는 2026-08-09 배포되어 401(라우트 가동)을 반환하며, 앱 엔드투엔드 실측만 남았다.

- SSE 연결 시 메시지 이벤트를 즉시 반영하고 열린 메신저·전역 inbox의 확인 폴링은 각각 약 1분·5분으로 낮춘다.
- SSE 미연결 시 열린 메신저는 포그라운드 약 3초·백그라운드 약 30초, 전역 읽지 않음·알림은 약 30초로 폴링한다.
- 첫 폴링은 알림을 띄우지 않고 이후 새 메시지는 OS 알림과 dock/taskbar 배지로 알린다. 데스크톱 알림은 renderer의 Web Notification이 아니라 Electron main의 native Notification 경로를 사용해 Windows AppUserModelID·시스템 알림 설정을 따른다.
- 팝아웃이 포커스된 채널은 중복 OS 알림을 억제한다.
- 화면이 포커스되고 메시지 끝을 보고 있을 때만 새 메시지를 읽음 처리하며 읽음 커서는 뒤로 가지 않는다.
- 보낸 메시지 아래에는 같은 프로필 구성원 중 아직 읽지 않은 인원 수를 표시하며, 모두 읽으면 숫자를 숨긴다. 인원 계산은 CSV 프로필 멤버 목록과 서버의 단조 읽음 커서를 기준으로 한다.

### 7.2 실시간 클라이언트와 서버 확장 기반

서버 코드에는 SQLite WAL, 전역 DB 락 제거, `clientMessageId` 멱등 전송, 프로필별 in-process pub/sub, 메시지·읽음·snapshot·presence 이벤트, 25초 하트비트가 구현되어 있다. 기존 폴링 API는 그대로 유지한다.

앱에는 main 프로세스 단일 SSE 연결, 지수 백오프 재연결, 폴링 fallback, 멱등 전송 큐와 pending·재시도·재전송 UI, `onlineLogins` 상태와 온라인 표시가 구현되어 있다. 연결이 끊기면 잘못된 온라인 상태를 보여주지 않도록 프레즌스 UI를 숨긴다. 서버 이벤트의 `isAuthor`는 수신 사용자의 로그인과 `authorLogin`을 비교해 다시 계산한다.

운영 VPS에는 `v1.4.186`의 login 정규화 서버 모듈까지 배포됐다. 합성 인증 세션으로 `GET /events` HTTP 200과 2초 연결 유지, 워크스페이스·메신저·멤버 API 200, 세션 폐기와 잔존 없음까지 확인했다. 사용자 두 계정의 1초 내 이벤트 수신·프레즌스 표시는 GUI 실측으로 최종 확정한다.

SSE를 배포할 때 서버는 반드시 `ThreadingHTTPServer`여야 한다. 단일 스레드 서버에서 장시간 SSE 연결을 열면 다른 요청을 막는다.

## 8. 회사 메일 연동

### 8.1 연결과 보안

메일은 앱이 직접 IMAP/SMTP 비밀번호를 계속 들고 호출하는 방식이 아니다. 로그인 시 VPS가 자격 증명을 메모리 세션에 연결하고 앱·Hermes는 불투명 토큰만 보낸다.

- IMAP: `play.samwooeleco.com:993`, SSL.
- SMTP: 운영 서비스는 `play.samwooeleco.com:25`로 설정돼 있으나 메일 서버가 STARTTLS를 제공하지 않아 발송이 차단돼 있다(애플리케이션은 STARTTLS 필수, 소스 기본 포트는 587).
- 기본 세션 TTL 8시간, 네트워크 제한 20초.
- 받은메일 목록 최대 50개.
- 발송 수신자 최대 20명, 본문 최대 256KiB.
- 발신자는 로그인한 메일함으로 고정한다.
- Hermes 메일 스킬은 발송 전에 사용자에게 수신자·제목·내용 확인을 받는다.

지원 API는 `/mail/list`, `/mail/read`, `/mail/send`(운영 차단), `/mail/attachments/list`, `/mail/attachments/save-to-workspace`다. 앱은 풀 메일 클라이언트 화면을 제공하지 않으며 주 사용 경로는 Hermes 팀봇의 메일 스킬이다.

2026-08-10 외부 프로토콜 점검에서 IMAPS 993은 TLS 1.3과 `play.samwooeleco.com` 인증서 검증을 통과했다. 반면 SMTP 587과 25는 EHLO 응답에서 STARTTLS를 제공하지 않았고 465는 연결을 거부했다. 현재 서버의 `smtplib.SMTP(...).starttls()` 경로로는 발송할 수 없다. 평문 인증으로 낮추지 않으며, 메일 서버에서 STARTTLS를 활성화하거나 별도 TLS submission 엔드포인트를 제공하기 전까지 발송 기능은 운영 차단 상태로 본다.

### 8.2 첨부파일 처리

메일 읽기는 본문과 첨부 메타데이터만 반환한다. 첨부 저장은 VPS가 IMAP에서 바이너리를 읽어 Nextcloud 워크스페이스로 직접 전송하므로 바이너리가 봇 프롬프트나 사용자 앱을 통과하지 않는다.

- RFC2047·RFC2231·EUC-KR 파일명과 inline filename을 처리한다.
- 저장 가능한 첨부 1개 최대 16MiB.
- 같은 세션의 메일 소유자와 같은 프로필의 워크스페이스 쓰기 권한을 모두 확인한다.
- 기본 저장 위치는 워크스페이스의 `mail/<파일명>`이다.
- 같은 이름이 있으면 덮어쓰지 않고 `(2)` 형식으로 새 이름을 만든다.
- 저장 후 워크스페이스 리비전을 갱신해 다른 사용자에게 변경을 알린다.

메일 첨부 파이프라인은 저장소에 구현됐고 관련 VPS 모듈은 2026-08-09 배포됐다. 다만 실제 계정의 IMAP 첨부를 제한 서비스 계정으로 Nextcloud에 저장하는 통합 시험은 미완료이므로 운영 완료로 단정하지 않는다.

## 9. VPS 서버와 데이터 저장

서버는 `/opt/samwoo-auth` 배포를 기준으로 하는 Python 서비스다. 현재 운영 응답에서 Python `3.12.3`을 확인했다. 핵심 인증·워크스페이스·메신저 경로는 Python 표준 라이브러리와 SQLite를 사용하며 메일 메모리 보호용 `cryptography`는 선택 사항이다.

| 저장 대상                      | 위치·방식                                                                                 |
| ------------------------------ | ----------------------------------------------------------------------------------------- |
| 워크스페이스 세션·공유·댓글    | SQLite `/opt/samwoo-auth/workspace-shares.db`                                             |
| 프로필 메시지·읽음 커서        | 같은 SQLite DB                                                                            |
| 메신저 직원 표시명·프로필 멤버 | VPS 런타임 CSV (`user-display-names.csv` 우선, `role-map.csv` fallback), 저장소 커밋 금지 |
| 공유 파일                      | Nextcloud WebDAV                                                                          |
| 메일 비밀번호                  | 서버 프로세스 메모리, TTL 만료·revoke 시 폐기                                             |
| 예약 작업·최근 실행            | 각 노트북 Electron localStorage `samwoo.schedules.v1`                                     |
| 예약 결과                      | 등록 프로젝트의 `SAMWOO-예약결과/<예약 ID>/` Markdown                                     |
| 로컬 동기화 manifest           | 각 노트북 Electron userData, 권한 `0600`                                                  |

SQLite는 WAL, `busy_timeout=5000`, `synchronous=NORMAL`, foreign keys를 사용한다. 테이블은 `workspace_sessions`, `workspace_shares`, 댓글, `profile_messages`, `profile_message_reads`이며 기존 데이터를 파괴하지 않는 `CREATE TABLE IF NOT EXISTS`/추가 마이그레이션 방식이다.

온라인 SQLite backup API를 쓰는 `backup-workspace-db.sh`와 14일 보관 정책이 구현되어 있다. 운영 cron `0 3 * * *`이 등록돼 있으며, 2026-08-10 W11 배포 전 백업과 마이그레이션 후 일일 백업을 직접 실행해 무결성·0600 권한·마이그레이션 원장 7개 보존을 확인했다. 임시 DB 검증에서는 14일 초과 파일 삭제도 통과했다. SSE 이벤트 버스는 단일 프로세스 메모리 기반이므로 현재 단일 서버 구성을 전제로 한다.

프로필 멤버 API는 Bearer 토큰의 서버 세션에서 프로필을 결정하며 클라이언트가 조회 프로필을 선택할 수 없다. CSV는 mtime 변경 시 재로딩하고 읽기 실패 시 login 표시로 기능 저하한다. 이 디렉터리는 메신저 전용으로 에이전트·Hermes 프로필 명칭에는 관여하지 않는다.

## 10. 업데이트, 빌드와 사내 설치

### 10.1 빌드·공개 절차

`.github/workflows/build-samwoo-windows.yml`은 수동 실행만 허용한다.

1. 관리자가 upstream 변경과 SAMWOO 변경을 검증한다.
2. GitHub Actions의 Windows 2022 runner에서 의존성 설치, 지정 통합 테스트, 전체 Python 서버 테스트를 실행한다.
3. Windows 앱을 빌드하고 사내 인증서로 서명한다.
4. 인증서 해시·publisher·서명과 `latest.yml`·blockmap·버전 일치를 검증한다.
5. GitHub에는 **Draft 릴리스**로 만든다.
6. 관리자가 산출물과 해시를 확인한 뒤 Public release로 공개한다.

Windows NSIS 설치기는 전체 사용자용 one-click 방식이다. 설치 마법사와 경로 선택 없이 진행 표시만 보여주고 완료 후 자동 종료·실행하며 바탕화면 바로가기를 만든다. 전체 사용자 설치는 Windows 권한 정책상 최초 설치와 이후 업데이트에서 UAC 승인을 요구할 수 있다. 산출물 이름은 `samwoo-orca-windows-setup.exe`다.

### 10.2 설치된 앱의 업데이트

앱은 공개 GitHub release의 `latest.yml`을 확인한다. 자동 점검은 대략 하루 주기이며 공개 직후 파일 전파가 불완전한 경우 약 1시간 뒤 재시도한다.

사용자가 업데이트 버튼을 누르면 앱이 설치 파일과 blockmap을 다운로드하고 단계·진행률을 표시한다. Windows에서는 진행 표시 프로세스를 앱 종료 뒤에도 유지하고 NSIS의 진행 표시로 이어서 설치한 뒤 SAMWOO-ORCA를 다시 실행한다. 전체 사용자용 NSIS는 실행 때 UAC 승인을 요구할 수 있으므로 이를 “UAC 없는 완전 무인 업데이트”로 표현하지 않는다. 앱이 닫히지 않을 때를 위한 약 20초 watchdog이 있다.

내부 인증서 설치, 설치 파일 해시·서명 검증, Tailscale 설정, OpenSSH Client 준비와 인바운드 SSH 차단은 사내 설치 키트의 계약이다. Git·Python·uv 오프라인 파일이 없으면 고정된 공식 URL에서 내려받아 SHA-256을 검증하며, 전체 사용자 설치와 기존 사용자 설치 경로를 모두 확인한다. 실제 키·비밀번호는 저장소에 두지 않는다. Nextcloud 설치 키트의 마지막 업로드 상태는 이번 감사에서 재확인하지 않았으므로 별도 운영 확인이 필요하다.

## 11. upstream Orca에서 유지하는 기능

SAMWOO 커스텀 기능은 upstream 기능을 대체하지 않고 추가한다. 다음 기반 기능을 유지한다.

- 여러 CLI 에이전트를 나란히 실행하고 Git worktree별로 격리·비교·병합.
- 분할 터미널, 재시작 후 scrollback, 에이전트 상태·알림.
- 파일 탐색기·편집기, Markdown·이미지·PDF 미리보기, 파일·이미지의 에이전트 전달.
- 내장 Chromium 브라우저, Design Mode, 브라우저 자동화·computer use.
- Git 변경·diff 검토·주석·commit·branch·worktree 관리.
- GitHub·GitLab 등 provider별 소스 제어 경로와 Linear 등 upstream 연동.
- SSH worktree, 원격 파일·터미널·Git, 포트 포워딩·재연결, Windows WSL 실행.
- 빠른 열기, 계정 전환·사용량 표시, skills·plugins·MCP, Orca CLI와 자동화.

의도적 차이는 Tasks 사이드바 렌더 제거뿐이며 내부 구현을 삭제하지 않았다. SAMWOO 워크스페이스 공유는 GitHub 기능과 독립적이므로 사용자가 GitHub 계정 없이도 동작한다.

## 16. 검증·배포 게이트

- Tasks 탭 접근 제거는 의도된 변경이며 회귀가 아니다.
- 각 기능 단계는 지시서의 focused test, TypeScript 검사, oxlint, max-lines ratchet, i18n coverage를 통과해야 한다.
- 서버 변경은 기존 폴링 API와 구버전 앱을 깨지 않아야 하며 마이그레이션은 기존 데이터를 보존해야 한다.
- SSE 배포 전 `ThreadingHTTPServer`와 동시 요청 시험은 0순위다(2026-08-09 확인 완료).
- **새 창·새 React 루트를 추가하면 패키지 빌드 기준 GUI 실행을 릴리스 전에 확인한다.** dev 실행과 단위 테스트만으로는 Provider 컨텍스트 누락 같은 런타임 크래시를 잡지 못한다(`v1.4.183` 사례).
- NSIS 훅을 추가·수정할 때 assisted 전용 변수·페이지는 `!ifndef ONE_CLICK` 안에만 둔다. 관련 `!define`과 매크로는 함께 옮긴다.
- Git 변경은 native·WSL·SSH별 Git 2.25 baseline과 GitHub 외 provider를 고려한다.
- UI는 `docs/STYLEGUIDE.md`, `main.css` 토큰과 기존 shadcn primitive를 따른다.
- lint disable이나 per-file max-lines 예외로 게이트를 우회하지 않는다.
- 빌드·배포는 사용자의 명시적 지시가 있을 때만 실행한다.

### 17.2 남은 위험·미확인

1. **SMTP 발송 차단**: 운영 서비스는 SMTP 25를 사용하지만 메일 서버의 587·25 포트가 STARTTLS를 제공하지 않고 465는 닫혀 있어 현재 보안 계약으로 발송할 수 없다. 평문 SMTP로 폴백하지 않는다. IMAPS 연결은 정상이나 실계정 조회, 첨부의 IMAP→Nextcloud 저장, 봇의 대화 요약·타 프로필 차단은 사용자 자격 증명이 필요한 시나리오로 남는다.
2. W11 서버 모듈 배포가 완료돼 실명 조회가 구 서버에 막히는 과도기는 종료됐다. 운영 `role-map.csv` fallback으로 18명을 정상 로드했으며, 실제 운영 파일의 mtime 변경을 동반하는 핫 리로드 실측만 코드 테스트 상태로 남아 있다.
3. Nextcloud 상태와 서비스 계정 WebDAV 읽기·쓰기·삭제는 정상이다. 사내 설치 키트 최신 업로드 상태와 Windows 설치 키트의 Tailscale 온라인 fallback은 실 PC 확인이 필요하다.
4. VPS에 커널 업데이트 재부팅 보류 알림이 있다. 서비스 동작에는 지장 없으나 유휴 시간에 재부팅 후 서비스 자동 복구를 확인하는 것이 좋다.
5. Tailnet 분리: 이 관리용 맥은 `tail5c6263`에, VPS·직원 PC는 `tail730b48`에 있어 맥에서 VPS 직결이 안 된다. Hostinger 웹 터미널로 운영 작업은 가능하지만 직접 API 실측에는 직원 tailnet 연결이 필요하다.
6. 설치기 전환 과도기: `v1.4.184` 이하는 사용자별 assisted 설치본이므로 `1.4.185`로 올라가는 이번 1회는 기존 마법사 화면이 보일 수 있다. `1.4.185`가 설치된 뒤부터 이후 설치·업데이트가 진행 표시만 나오는 one-click 방식으로 동작한다. 전체 사용자 설치 특성상 UAC 승인은 남는다.
